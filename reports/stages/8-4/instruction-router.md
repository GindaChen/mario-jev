The user authorized a two-level DJev harness after repeated failed fresh-stage trials. A retrieved note can now define instruction_router: DJev first selects an instruction set; a second DJev call chooses the action from that set. The harness does not choose the route label. Logs retain the instruction-selection request, probabilities and choice, followed by the action request and response. Optional action_state_fields exposes just the facts needed by that instruction set. Existing profiles without a router retain their original request path.

This is hierarchical prompting on the same unchanged model, not a stronger online model or weight training. The GPT-authored profiles and location-based note retrieval remain substantial engineered assistance. The emulator waits for both inference calls; it is not real-time play.
